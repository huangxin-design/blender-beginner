# 花穗绽放｜制作回顾

本页依据现存任务记录、场景、脚本和最终交付报告压缩整理。下面是阶段摘要，不是逐字聊天；没有用重写的提示词补造历史回复。

| 阶段 | 当时想解决的问题 | 留下的结果 |
| --- | --- | --- |
| 参考拆解 | 把用户说的“粒子效果”落实为沿花茎分布、逐层展开的花朵 | 以两支细长花穗、暖棕背景、珊瑚与桃色花瓣为主要关系，做程序化近似重建 |
| v001–v002 | 花瓣不够展开、颜色与花茎关系需要调整 | 加宽花瓣、扩大开放态，保留花芽大小，调整双面红桃色与花茎长度 |
| v003 早期成片 | 让工程搬移后仍能播放开花动画 | 保留 54 层形态键、156 实例，修改数学表达式，使 216 条驱动在关闭自动执行时仍可原生求值；交付 720p、8 秒动画 |
| 4K 升级 | 用户增加聚焦感、轻雾、后景虚化与 HUANGHUAYU 水印 | 在 v003 保存工程上继续修改，保留花瓣几何与开花节奏，调整相机、后景植物和体积光 |
| v004–v005 小样 | 雾太浓、颗粒感影响主体 | 去掉高频雾纹理，调整体积里的灯光位置，反复查看原生局部 |
| v006 最终版 | 清楚的主花穗与柔和的后景能同时成立 | 薄雾、远处柔光、开头轻微聚焦、内置字体半透明水印；输出原生 4K 帧 |
| 完整交付检查 | 排除编码、解码与播放器问题 | 两版视频各 240 帧的原生软硬解码画面一致；代表帧、原生裁切和两版实际播放器窗口分别检查 |

最终渲染采用分段完成：先确认第 155、240 帧的原生 4K 样张，后续复用这两张，实际续跑其余 238 帧。渲染耗时因此不能把“进度 240/240”直接当成这一次重新渲染了全部 240 帧。[完整统计与检查范围](verification.json)

初次交付验证也有返修记录：源 PNG 为 sRGB，检查程序最初错误地预期另一种传递标签；另外，软硬解码转 RGB 前的 NV12 与平面 YUV 排列不同。最终统一两路排列与转换方式后，原生全片像素差异为零。修正的是检查方式，未通过缩放或放宽阈值隐藏差异，也没有因此改写最终视频。

旧版 v003、v004、v005 仍保留在作者本地项目。这个公开案例只收录 v006 最小交付，不复制旧版全套资产。最终画面仍是对参考风格的程序化重建；花瓣和运动节奏与原参考有差别，不称为逐帧还原。
