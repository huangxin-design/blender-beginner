# 渲染进度与动态预估

用于用户要求本次渲染显示进度、剩余范围或倒计时时。只观察本次启动的渲染；本地监听不逐秒调用模型。仅询问原理或估算时，不启动渲染。

## 首版可执行范围

`scripts/render_job.py` 使用 Blender 内置 Python 打开后的活动场景，在全新绝对路径下生成一个明确帧计划的 PNG 静图或序列。由 `scripts/run_blender.py` 启动并控制墙钟超时，既有工程通过 `--blend` 传入；不保存或覆盖输入 `.blend`。

```text
python <skill>/scripts/run_blender.py --blender <Blender绝对路径> --blend <已有工程.blend> --script <skill>/scripts/render_job.py --log-dir <全新绝对日志目录> --timeout 600 --progress -- --output-dir <全新绝对输出目录> --frames 1,3,5
```

单图使用 `--frames 1`。帧计划可以不连续；每个编号只能出现一次。计划顺序决定渲染顺序。输出命名为 `frame_000001.png` 等。换工程版本、引擎、分辨率、采样配置、设备或配色后建立新的运行，不能套用旧速度。复杂度随动画变化时，即使设置未变也可能突然变慢。

失败后重跑使用新的日志目录、输出目录和运行 ID，保留失败日志及部分输出；首版不自动续帧。负帧计划可写成 `--frames=-1,1,3`。

此 worker 保留当前渲染设置，要求原场景输出格式已经是 PNG。非 PNG、缺少相机、多视图、合成器 File Output 或活动视频序列不能套用该路径；先明确实际交付需要，再对获授权的副本配置相应输出。不为获得进度静默关闭效果或把视频改成静图。不同镜头/模拟或多输出专用脚本未建立可靠帧事件时，只报告已有日志阶段和耗时。

## 用户看到什么

- 当前阶段与已用时；首次初始化可能长时间无日志。
- 已完成计划帧数 / 总帧数，以可靠帧事件确认，不数 `Saved` 行，不把最高帧号当计数。
- 日志提供时，单独显示“本帧采样预计剩余”。`Remaining=0`、满采样和引擎 `Finished` 均不代表文件已保存。
- 首帧耗时单列，可能包含初始化；至少再积累三个同计划完整帧，才使用最近八个后续帧的最短/最长耗时形成经验范围。它不是统计置信区间，不能保证未观测镜头同速；后续慢帧保留在历史与窗口内。
- 当前帧超出已有范围，撤回 ETA 并重新估计；慢帧完成后范围可以上升。默认超过 30 秒没有新进度，撤回 ETA，保留已用时和最后真实更新时间；静默不自动判定卡死。
- 不把采样时间外推为模拟、编码或画面验收的剩余时间。单图和很短序列没有足够历史时，整体剩余保持未知。

`updated_at` 是快照更新时间，`progress_updated_elapsed` 是最近识别到的真实进度时刻。刷新页面或写快照不能伪装为新进度。失败、超时、中断有各自终态，不继续显示剩余倒数。

## 证据与完成边界

worker 在每帧 `bpy.ops.render.render(write_still=True)` 返回成功、计划主 PNG 非空后，发出并刷新带 `BLENDER_RENDER_EVENT ` 前缀的 JSON。耗时使用 `time.perf_counter()`，覆盖设置帧到渲染返回（包括保存），不从批量日志的读取间隔推算。事件含运行 ID、计划帧、发出时间、输出路径和文件大小；完整历史保留在运行日志中。

`render_progress.RenderProgress` 的接口为 `feed(line, now_elapsed)`、`snapshot(now_elapsed)`、`finish(status, now_elapsed)`。仅 worker 事件建立可靠帧计划与完成记录；原生日志仅补充 Cycles/EEVEE 采样信息。重复计划或帧事件不会增加计数；新运行 ID 重新收集历史。未知格式降级为已用时与未知剩余。

完成分三层：

1. `frames_complete=true`：计划帧渲染调用返回且主输出非空；属于存在性检查。
2. `status=completed`：Blender 进程正常退出。可能没有可核验帧计划，也可能是其他脚本；不自动推出第 1 层。
3. 图像可读、分辨率和画面正确：另行检查，默认 `visual_verification=unverified`。高清视频还必须遵守项目现行软件/硬件逐帧画面对比及实际播放器验收，不能由该面板自动勾选。

日志事件是受控脚本的本地进度约定，不是安全隔离或针对恶意脚本的认证。只运行已经审阅的脚本和获授权工程；对不可信 `.blend`、第三方插件及额外输出风险，延用原有运行边界。
